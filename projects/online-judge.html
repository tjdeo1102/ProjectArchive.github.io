교내 채점 서비스 · 2024.01–08 · 7인 팀 · 백엔드 팀장

온라인 저지

학생이 문제를 제출하고 교수와 관리자가 결과를 조회하는 온라인 저지를 고도화했습니다. 기존 문제를 옮기면서 수식과 이미지가 새 화면에서도 읽히는지 확인했습니다.

데이터 이전

계정과 문제를 옮기는 기준

Django·MariaDB 환경에서 새 ERD를 구성했습니다. 중복되거나 정보가 유실된 계정은 책임자와 협의해 백업을 보존하고 일괄 이전에서 제외했습니다.

문제 본문 검증

변환 규칙을 작성하고 수식·이미지·특수문자가 있는 문제를 직접 열어 이전 결과를 확인했습니다.

서비스 운영

접근 범위와 배포

관리자·교수·학생의 권한에 맞게 서버 조회를 나누고 문제 PDF 출력과 Nginx 배포 설정을 맡았습니다. 약 4개 분반에서 1차 운영한 뒤 피드백을 반영했습니다.

온라인 저지 백엔드 기능 개발

기능 기획 배경

오픈소스 온라인 저지를 실제 서비스로 활용하기 위해 문제와 시험을 관리하고, 제출 코드를 채점기에 전달하며, 결과를 사용자에게 반환하는 백엔드 기능의 구현과 연동이 필요했습니다.

구현 방식

  • 문제, 시험, 제출 및 채점 결과 간 데이터 흐름 분석
  • 채점기와 연동되는 요청 및 결과 처리 로직 구현
  • 사이트에 내포된 주요 기능이 실제로 동작하도록 백엔드 로직 구현
  • 채점 결과와 시험 내용을 PDF로 생성하는 기능 구현

구현 성과

  • 문제 제출부터 채점 결과 확인까지 이어지는 핵심 백엔드 흐름 구현
  • 채점 결과와 시험 내용을 PDF 문서로 제공하는 기능 구축

이기종 스키마 기반 DB Migration

기능 기획 배경

기존 시스템과 신규 온라인 저지는 DB 스키마와 문제 데이터 표현 방식이 서로 달랐습니다.

단순한 레코드 복사만으로는 테이블 관계가 깨지거나 문제 설명과 입·출력 예제가 신규 사이트에서 정상적으로 표시되지 않을 수 있어, 데이터 구조와 콘텐츠 형식을 함께 변환하는 마이그레이션이 필요했습니다.

또한 기존 데이터 중 일부 필드가 누락되거나 불완전한 경우에는 임의로 값을 결정하지 않고 서비스 운영 담당자와 처리 기준을 합의해야 했습니다.

분석 및 설계

  • 기존 시스템과 신규 시스템의 ERD 비교
  • 테이블, 컬럼, 기본 키·외래 키 및 개체 간 관계 분석
  • 문제, 시험, 사용자, 제출 및 채점 결과 개체의 대응 관계 확인
  • DB 개체 매핑 정의
  • 기존 필드와 신규 스키마 필드 간 매핑 규칙 설계
  • 직접 이전할 데이터와 변환이 필요한 데이터 구분
  • 관계 및 이전 순서를 고려한 마이그레이션 절차 설계
  • 누락 데이터 처리 기준 수립
  • 필수 필드와 데이터 누락 여부 점검
  • 누락되거나 해석이 필요한 데이터 목록화
  • 담당 교수진과 소통하여 보완, 기본값 적용 또는 이전 제외 등 처리 방식 결정

문제 콘텐츠 변환 및 이식

  • 기존 문제 설명 구조와 신규 사이트의 표현 형식 비교
  • 문제 본문, 입·출력 설명 및 예제 데이터의 반복 패턴 분석
  • 기존 문제의 내용과 예시를 신규 사이트 형식에 맞게 바꾸는 변환 로직 구현
  • 변환된 문제 데이터를 신규 스키마의 대응 개체와 연결하여 이식
  • 특수 형식과 예외 데이터는 별도로 점검하여 수동 처리 기준 적용

검증 방식

  • 이전 전후 테이블별 레코드와 주요 관계 비교
  • 문제 본문, 입·출력 설명 및 예제의 표시 결과 확인
  • 누락 데이터 처리 결과와 교수진이 협의한 기준의 적용 여부 검증
  • 이전된 문제, 시험 및 채점 관련 기능의 실제 사이트 동작 확인

구현 성과

  • ERD 기반 DB 개체 매핑을 통해 상이한 스키마 간 데이터 이전 구조 설계
  • 누락 데이터를 식별하고 이해관계자와 합의한 기준에 따라 일관되게 처리
  • 기존 문제 콘텐츠를 신규 사이트의 형식과 표현 방식에 맞게 자동 변환하여 이식
  • 데이터 관계와 화면 표현을 함께 검증하는 마이그레이션 절차 구축

Nginx 웹 서버 배포

기능 기획 배경

백엔드 애플리케이션과 정적 리소스를 외부 서비스로 제공하기 위해 요청 경로를 분리하고 전달할 웹 서버 구성이 필요했습니다.

구현 방식

  • Nginx 리버스 프록시를 설정하여 클라이언트 요청을 백엔드 서비스로 전달
  • 정적 리소스와 생성 파일을 제공하기 위한 정적 파일 라우팅 구성
  • 서비스 경로와 포트를 운영 환경에 맞게 정리

구현 성과

  • Nginx를 진입점으로 사용하는 웹 서비스 배포 환경 구성
  • 백엔드 요청과 정적 파일 요청의 라우팅 분리

로그 및 파일 관리 설계

기능 기획 배경

서비스 로그와 정적 파일을 일관되게 관리하고, DB 데이터와 로컬 파일 간의 관계를 명확히 할 필요가 있었습니다.

구현 방식

  • DB에서 관리할 파일 메타데이터와 로컬에 저장할 실제 파일을 구분
  • 로그 및 정적 파일의 저장 위치와 조회 흐름 설계
  • DB 레코드와 로컬 파일의 연결 및 관리 방식 정리

구현 성과

  • DB와 로컬 파일 시스템의 역할을 분리한 관리 구조 설계
  • 로그와 정적 파일을 일관되게 다룰 수 있는 기반 마련

기본 방화벽 설정

기능 기획 배경

웹 서버 공개 시 서비스에 필요한 접근은 허용하면서 불필요한 포트 노출은 제한할 필요가 있었습니다.

구현 방식

  • 서비스 운영에 필요한 포트 확인
  • 기본 방화벽 규칙을 설정하여 허용 포트를 제한
  • 외부 접근 경로와 서버 노출 상태 점검

구현 성과

  • 서비스 운영 범위에 맞춘 기본 네트워크 접근 제어 적용
